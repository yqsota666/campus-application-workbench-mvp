# 校园招聘秋招投递助手 MVP 后端设计

## 目标

后端先实现一条可迭代的本地 MVP 链路：

```text
每日搜索
  -> 抓取结果
  -> 人工确认抓取信息
  -> 确认入库
  -> 人工注册协作
  -> 简历预填草稿
  -> 最终人工提交
  -> 投递跟踪
```

第一版不做真实最终提交，不绕过验证码、短信验证、扫码登录或协议确认。所有自动化输出都必须可追踪、可退回、可人工确认。

## 核心原则

1. 抓取到的信息默认不可信。
2. 抓取结果默认进入 `capture_waiting_review`。
3. 只有人工确认来源、字段、截止时间和岗位适配后，才进入 `job_ready`。
4. 注册登录属于人工协作，不属于自动填表。
5. 简历预填只能生成草稿，最终提交必须人工确认。
6. 每个状态变化写入事件日志，方便后续审计和产品化。

## 模块划分

### Profile Store

读取并输出个人资料和求职偏好。

来源：
- `capture_v1/profile.json`
- `capture_v1/preferences.json`
- `capture_v1/sources.json`

### Capture Service

负责每日搜索和抓取结果归一化。

MVP 阶段先使用本地样例和来源配置生成抓取结果，不直接访问复杂招聘系统。后续可以替换为：
- 企业官网抓取器
- 微信公众号线索收集
- 搜索引擎 API
- n8n workflow
- LLM 抽取器

输出状态：
- `capture_waiting_review`

### Capture Review Gate

人工确认抓取信息。

确认项：
- `source_confirmed`：来源可信，有官网或可信公众号原文。
- `fields_confirmed`：公司、岗位、地区、批次、投递入口等字段完整。
- `deadline_confirmed`：截止时间确认；缺失时必须标记说明。
- `fit_confirmed`：符合校园招聘、地区A和计算机方向。

全部通过：
- 状态变为 `job_ready`

未全部通过：
- 状态变为 `needs_more_evidence`

### Job Library

管理已抓取和已确认岗位。

重要状态：
- `capture_waiting_review`
- `needs_more_evidence`
- `job_ready`
- `auth_waiting_for_user`
- `auth_ready`
- `prefill_ready`
- `submitted`
- `tracking`
- `closed`

### Auth Assist

注册登录协作模块。

系统可以：
- 创建注册协作任务。
- 记录卡点：验证码、短信验证、扫码登录、协议确认。
- 等待用户手动处理。
- 用户确认后写入 `auth_ready`。

系统不可以：
- 自动绕过验证码。
- 自动读取短信。
- 自动扫码。
- 自动替用户同意协议。

### Prefill Draft

登录态就绪后生成预填草稿。

规则：
- 高置信字段可以进入草稿。
- 中低置信字段进入问题队列。
- 最终提交不由后端触发。

## API 设计

### Health

`GET /api/health`

返回服务状态、版本和当前时间。

### Profile

`GET /api/profile`

返回个人资料。

`GET /api/preferences`

返回求职偏好。

`GET /api/sources`

返回来源配置。

### Capture

`POST /api/capture/run`

触发一次本地模拟抓取。输出的新岗位均进入 `capture_waiting_review`。

`GET /api/capture/runs`

查看抓取运行记录。

`GET /api/capture/today`

查看今天抓取到、等待确认的岗位。

`POST /api/capture/jobs/{job_id}/review`

人工确认抓取结果。

请求示例：

```json
{
  "source_confirmed": true,
  "fields_confirmed": true,
  "deadline_confirmed": true,
  "fit_confirmed": true,
  "notes": "官网原文和岗位方向已确认"
}
```

全部为 `true` 时，岗位状态进入 `job_ready`。

### Jobs

`GET /api/jobs`

支持按状态查询岗位。

`GET /api/jobs/{job_id}`

查看岗位详情。

### Auth Assist

`POST /api/auth-sessions`

为已确认入库的岗位创建人工注册协作任务。

`POST /api/auth-sessions/{session_id}/confirm`

用户完成注册登录验证后，确认 `auth_ready`。

### Prefill

`POST /api/prefill/{job_id}/draft`

在 `auth_ready` 后生成预填草稿。

### Events

`GET /api/events`

查看事件日志。

## 本地存储

MVP 使用 JSON 文件存储：

```text
backend/data/state.json
```

结构：

```json
{
  "jobs": [],
  "capture_runs": [],
  "auth_sessions": [],
  "prefill_drafts": [],
  "events": []
}
```

后续可以平滑替换为 SQLite/Postgres。API 和状态机不变。

## 安全边界

- 不保存验证码。
- 不保存短信验证码。
- 不保存账号密码。
- 不自动点击最终提交。
- 所有需要人工判断的节点都返回 `waiting_for_user` 类状态。
